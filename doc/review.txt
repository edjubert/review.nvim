*review.txt*   Commit-by-commit merge/pull request review

==============================================================================
INTRODUCTION                                                     *review.nvim*

review.nvim opens a GitLab MR, GitHub PR or Codeberg PR URL, lists its commits,
and renders read-only inline diffs with selectable additions and deletions.
Comment drafts are local until explicit publication.

Requires Neovim 0.11+, git, and the API client for the review host:
authenticated glab for GitLab, authenticated gh for GitHub, curl for Codeberg.
Other providers' clients are optional. GitLab and GitHub Enterprise Server
hosts are supported. Codeberg support is limited to https://codeberg.org.

Authenticate with glab auth login --hostname <host> for GitLab, or
gh auth login --hostname <host> for GitHub. Check credentials with auth status.
No interactive login session needs to stay open. The plugin delegates API
requests to the CLI and never reads credential files itself.
Git fetching uses your Git credentials separately (SSH by default).

For Codeberg, create a token in https://codeberg.org/user/settings/applications
and set CODEBERG_TOKEN in the environment inherited by Neovim. Use repository
access (read:repository for private reads, write:repository for publication).
Public API reads need no token. curl sends the token through stdin, never
process arguments or temporary files; credential files are not read.
CODEBERG_TOKEN authenticates API requests, not Git fetches.
Use clone_protocol = "https" for anonymous Git access to public repositories.

==============================================================================
COMMANDS

:Review [url]                                                       *:Review*
    Open a GitLab MR, GitHub PR or Codeberg PR in a new tab. Without an
    argument, prompt for its URL. The URL selects the provider automatically.
    Codeberg URLs use https://codeberg.org/owner/repo/pulls/123.

:[range]ReviewComment                                        *:ReviewComment*
    Draft a comment on the current diff line or a visual line selection.
    Ctrl-S or :w in the comment editor saves locally. q cancels.

:ReviewDrafts                                                *:ReviewDrafts*
    Inspect, edit or delete local drafts.

:ReviewThreads                                              *:ReviewThreads*
    Read all discussions across the MR/PR.
    Enter on a discussion jumps to its comment line; q closes the window.

:ReviewRefresh                                              *:ReviewRefresh*
    Reload the MR/PR, commits, diffs and discussions in the existing tab.
    Keep the selected commit and file when they still exist; otherwise open
    the complete MR/PR if the selected commit was replaced.
    Preserve the cursor when the displayed Git revisions are unchanged.
    Keep local drafts and their original positions.
    A failed refresh leaves the previously loaded review available.
    Also retries a failed initial load.

:ReviewSubmit                                                *:ReviewSubmit*
    Show the exact drafts, then request explicit publication.
    If the review's diff refs changed, drafts remain local.
    GitHub drafts publish as PR review comments; no approval is submitted.
    Codeberg drafts publish as COMMENT reviews; no approval is submitted.
    Finish or discard a pending Codeberg browser review before submitting.

:ReviewClose                                                  *:ReviewClose*
    Close the review tab.

==============================================================================
MAPPINGS

Panel: <CR> opens the selected commit or file.
Diff: <leader>rc drafts a comment in normal or visual mode (configurable).
Both: ]c/[c next/previous commit; ]f/[f next/previous file;
      ]h/[h next/previous change block in the current file (counts supported);
      gA complete MR/PR; gd local drafts;
      gt discussion under the cursor (diff only); gT all discussions;
      <leader>rr refresh the review;
      <leader>rs preview and submit drafts; q close.

Opening a file focuses its first change block, opens any folds covering that
line and centers the diff view there. A refresh keeps the previous cursor
when the displayed Git revisions are unchanged.

The sidebar colors follow the colorscheme. Shortcut hints remain in a muted
footer while the tree scrolls. Customize ReviewHelp, ReviewCommit,
ReviewDirectory, ReviewFileAdded/Modified/Deleted/Renamed and ReviewSelected.

Ctrl-S in the comment editor saves a persistent local draft, exits insertion
and closes the editor. Publication requires :ReviewSubmit.

Deleted rows are real buffer lines. The buffer row number is not the original
file line number: review.nvim maps selected rows to provider old/new positions.

==============================================================================
DISCUSSION NAVIGATION                                        *review-threads*

gt opens discussions attached to the cursor's diff line. Any line inside a
commented range works. Several discussions on the same line open together.
In commit views, current-review discussions are mapped to unchanged lines;
comment ranges must remain contiguous and unchanged.
gT or :ReviewThreads opens all discussions, including general comments.

In the discussion window, j/k moves through the text, Enter jumps to the
discussion's file and comment line, and q closes the window.
Enter works from headings, locations, messages and replies.
The jump focuses the appropriate old/new side, opens folds and centers the
cursor. When needed, it opens the complete MR/PR comparison.

Older comments are mapped to the current review only when their line is
unchanged. If the line was rewritten/deleted, the file is no longer in the
review diff, or its original revision is unavailable, the discussion stays
open with an explanatory message. General comments have no line to jump to.

==============================================================================
CONFIGURATION                                                  *review-setup*

>lua
    require("review").setup({
      panel_width = 44,
      keymaps = {
        comment = "<leader>rc",
        submit = "<leader>rs",
        refresh = "<leader>rr",
      }, -- false disables a mapping
      clone_protocol = "ssh",
      repo = nil,
      cache_dir = vim.fn.stdpath("cache") .. "/review",
      state_dir = vim.fn.stdpath("state") .. "/review",
    })
<

An existing matching repository is used without switching branches.
Otherwise the plugin fetches a bare repository into cache_dir.
Local drafts are stored in state_dir/drafts/.

==============================================================================
COMMENT POSITIONS                                            *review-comments*

Commit-view comments are mapped to the current MR/PR diff, not posted as standalone
commit comments. A line rewritten by a later commit must be selected again in
the complete MR/PR view (gA). Ranges must cover one contiguous side of the diff.
Providers require the selected lines to be inside their diff context.

GitHub uses line/side and start_line/start_side for ranges. Removed lines
belong to LEFT; added/current lines belong to RIGHT.
GitHub's REST API does not expose a discussion's resolved state. Outdated
comments are labeled. PRs with more than 3000 changed files are rejected
because the files API cannot return a complete list. Commit lists above 250
entries use the paginated comparison API with a matching PR commit count.

Codeberg uses old_position/new_position for the first selected line and
extra_lines_count for a range. Each local draft creates one COMMENT review.
Codeberg can include existing pending browser comments when creating a review;
the plugin checks for a pending review before sending each draft. If one exists,
local drafts remain saved until the browser review is finished or discarded.
Review comments appear individually with resolved/stale indicators when exposed.
Comments whose commit cannot be matched to the current diff remain readable in
:ReviewThreads without an inline marker.

GitLab's discussion card can show up to 16 diff lines ending at the comment's
last line. The range shown below the excerpt is the actual commented range.
The discussion API does not expose a context-size option.

If a publish request's outcome is unknown, automatic retry is blocked. Check
the provider and use :ReviewDrafts to explicitly allow retry or delete the draft.
