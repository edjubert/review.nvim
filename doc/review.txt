*review.txt*   Commit-by-commit merge/pull request review

==============================================================================
INTRODUCTION                                                     *review.nvim*

review.nvim opens a GitLab MR, GitHub PR or Codeberg PR URL, lists its commits,
and renders read-only inline diffs with selectable additions and deletions.
Comment drafts are local until explicit publication.

Requires Neovim 0.11+, git, and the API client for the review host:
authenticated glab for GitLab, authenticated gh for GitHub, curl for Codeberg.
Other providers' clients are optional. GitLab and GitHub Enterprise Server
hosts are supported. Codeberg support is limited to https://codeberg.org.

Authenticate with glab auth login --hostname <host> for GitLab, or
gh auth login --hostname <host> for GitHub. Check credentials with auth status.
No interactive login session needs to stay open. The plugin delegates API
requests to the CLI and never reads credential files itself.
Git fetching uses your Git credentials separately (SSH by default).

For Codeberg, create a token in https://codeberg.org/user/settings/applications
and set CODEBERG_TOKEN in the environment inherited by Neovim. Use repository
access (read:repository for private reads, write:repository for publication).
Public API reads need no token. curl sends the token through stdin, never
process arguments or temporary files; credential files are not read.
CODEBERG_TOKEN authenticates API requests, not Git fetches.
Use clone_protocol = "https" for anonymous Git access to public repositories.

==============================================================================
COMMANDS

:Review [url]                                                       *:Review*
    Open a GitLab MR, GitHub PR or Codeberg PR in a new tab. Without an
    argument, prompt for its URL. The URL selects the provider automatically.
    Codeberg URLs use https://codeberg.org/owner/repo/pulls/123.

:ReviewInfo                                                     *:ReviewInfo*
    Show the loaded MR/PR title and description in a read-only Markdown
    window. :q closes it. Empty descriptions display "No description provided."
    Use :ReviewRefresh to retrieve updated metadata.

:ReviewHelp                                                     *:ReviewHelp*
    Search commands, configured shortcuts, actions and contexts in Telescope.
    The preview shows the mapping and where each action applies. Disabled
    shortcuts are shown as unconfigured. Selecting an entry closes the picker
    without running a command. Requires telescope.nvim and plenary.nvim.
    Enable keymaps.help for a shortcut; the optional example uses <leader>r?.

:[range]ReviewComment                                        *:ReviewComment*
    Draft a comment on the current diff line or a visual line selection.
    :w in the comment editor saves locally. :q! cancels.

:ReviewReply                                                  *:ReviewReply*
    Draft a reply to an existing discussion on the current diff line.
    Any line in a commented range works. Select a discussion when several
    cover the line. :w saves locally; :ReviewSubmit publishes
    only after explicit confirmation. Supported on GitLab and GitHub.

:ReviewDrafts                                                *:ReviewDrafts*
    Inspect, edit or delete local drafts.

:ReviewOpenComment                                      *:ReviewOpenComment*
    Open the comment under the cursor in the system's default browser.
    In the diff, any line in a commented range works; choose a discussion
    when several cover the line. Open its root comment.
    In a discussion window, open the selected comment or reply.
    Report unavailable URLs or browser launch errors. Local drafts have
    no published URL. Supported on GitLab, GitHub and Codeberg.

:ReviewThreads                                              *:ReviewThreads*
    Read all discussions across the MR/PR.
    :ReviewJump on a discussion jumps to its comment line; :q closes the window.

:ReviewThread                                                *:ReviewThread*
    Read discussions attached to the current diff line or range.

:ReviewJump                                                    *:ReviewJump*
    In a discussion window, jump to the selected comment's diff line.

:ReviewNextCommit / :ReviewPrevCommit                    *:ReviewNextCommit*
    Select the next/previous commit in the review.

:ReviewNextFile / :ReviewPrevFile                            *:ReviewNextFile*
    Select the next/previous changed file.

:[count]ReviewNextChange / :[count]ReviewPrevChange         *:ReviewNextChange*
    Jump forward/backward through change blocks in the current file.

:ReviewComplete                                            *:ReviewComplete*
    Open the complete MR/PR comparison.

:ReviewPanel {action}                                         *:ReviewPanel*
    Act on the panel entry under the panel's cursor, from either review window.
    Actions: open, left, right, toggle, expand, collapse, collapse_all, expand_all.

:ReviewFiles [query]                                          *:ReviewFiles*
    Without a query, focus the search field just above the sidebar's commits.
    Type to filter changed files as you edit. Matching folders stay visible
    and start expanded. The counter shows matching files / total files.
    With a query, apply it directly without focusing the field.

:ReviewFilesClear                                        *:ReviewFilesClear*
    Clear the query and restore the unfiltered directory fold state.

:ReviewFilesPicker                                      *:ReviewFilesPicker*
    Search all changed files in Telescope, including files hidden by the
    sidebar filter. Selecting a hidden file clears that filter.
    Requires telescope.nvim and plenary.nvim.

:ReviewPipelines                                          *:ReviewPipelines*
    Browse an open GitLab MR's pipelines in Telescope. Select a pipeline to
    open its jobs, grouped beneath non-selectable stage headings and sorted
    by name within each stage. Search preserves the group order.
    Success is green, failure red, pending orange, running blue, and inactive
    jobs (including manual and created) grey.
    Highlight a job to load its log asynchronously. Its metadata appears
    above the log: name, ID, status, stage, user, dates, duration, queue time,
    runner, ref/commit and failure information when available.
    Logs retain ANSI foreground/background colors (16-color, 256-color, RGB)
    and bold/italic/underline/inverse/strikethrough styling. The first 16
    colors use g:terminal_color_0 through g:terminal_color_15 when configured.
    Leading ISO timestamps and GitLab stream prefixes are grey. Customize
    ReviewJobTimestamp to change their appearance; message colors are retained.
    Other terminal controls and GitLab section markers are removed.
    The preview scrolls to the end after loading; scroll up for its header.
    Long previews show the last 5,000 lines / 512 KiB with a truncation notice.
    Missing, erased or inaccessible logs display a message. Downstream
    triggers show downstream pipeline metadata instead of a job log.
    Finished previews are cached while browsing this list. Reselecting a
    job that has not finished reloads it after a three-second cache interval;
    logs do not poll in the background.
    Telescope's selection action on a job opens it in GitLab. Enable
    keymaps.pipeline_open for an additional browser shortcut, and
    keymaps.pipeline_back to return from jobs to the pipeline list.
    All Telescope selection variants, including split, tab and drop, use
    these picker actions; provider entries are not opened as local files.
    Requires telescope.nvim and plenary.nvim. GitHub and Codeberg pipeline
    details are not implemented. All requests are read-only.

:ReviewJobRefresh                                        *:ReviewJobRefresh*
    Reload the selected job's metadata and log from its Telescope picker
    or preview. Bypass cached results, even for a completed job, and scroll
    to the latest output. An already pending load is not duplicated.
    Enable keymaps.pipeline_refresh for a shortcut in normal/insert mode;
    the optional README example uses <C-r>. It defaults to false.
    All requests are read-only; this command does not rerun the CI job.

:ReviewToggleComments                                *:ReviewToggleComments*
    Show or hide discussion messages and replies below their diff lines.
    Keep the chosen state across files, commits and refreshes.

:ReviewRefresh                                              *:ReviewRefresh*
    Reload the MR/PR, commits, diffs and discussions in the existing tab.
    Keep the selected commit and file when they still exist; otherwise open
    the complete MR/PR if the selected commit was replaced.
    Preserve the cursor when the displayed Git revisions are unchanged.
    Keep local drafts and their original positions.
    A failed refresh leaves the previously loaded review available.
    Also retries a failed initial load.

:ReviewSubmit                                                *:ReviewSubmit*
    Show the exact drafts, then request explicit publication.
    If the review's diff refs changed, drafts remain local.
    GitHub drafts publish as PR review comments; no approval is submitted.
    Codeberg drafts publish as COMMENT reviews; no approval is submitted.
    Finish or discard a pending Codeberg browser review before submitting.

:ReviewClose                                                  *:ReviewClose*
    Close the review tab.

==============================================================================
OPTIONAL MAPPINGS                                           *review-mappings*

No mappings are defined by default. Every keymaps entry defaults to false,
including navigation, panel folds, document selection/closing, draft saving
and additional pipeline picker shortcuts.

Add only the mappings you want to your setup call or lazy.nvim opts.
All enabled mappings are buffer-local. Unset entries leave existing mappings
available. See |review-setup| for the optional Lua example.

Commands provide navigation without mappings: |:ReviewPanel| controls the tree,
|:ReviewComplete| opens the full comparison, |:ReviewNextCommit| and
|:ReviewNextFile| navigate commits/files, and |:ReviewNextChange| jumps changes.

The search field uses a prompt buffer: its native Enter accepts the query and
returns to the tree; Ctrl-C returns while keeping the filter. Enable
keymaps.filter_exit for an additional return shortcut. keymaps.search_files
focuses this field; keymaps.files_picker opens the separate Telescope picker.

Opening a file focuses its first change block, opens any folds covering that
line and centers the diff view there. A refresh keeps the previous cursor
when the displayed Git revisions are unchanged.

The sidebar colors follow the colorscheme. :ReviewHelp shows shortcut hints
in a searchable Telescope picker. Customize ReviewHelp, ReviewCommit,
ReviewDirectory, ReviewFileAdded/Modified/Deleted/Renamed and ReviewSelected.

:w in the comment editor saves a persistent local draft, exits insertion and
closes the editor. Enable keymaps.save_draft for an additional save shortcut.
Enable keymaps.close_document for closing/canceling review document windows.
Publication requires :ReviewSubmit.

Deleted rows are real buffer lines. The buffer row number is not the original
file line number: review.nvim maps selected rows to provider old/new positions.

==============================================================================
DISCUSSION NAVIGATION                                        *review-threads*

:ReviewThread opens discussions attached to the cursor's diff line. Any line
inside a commented range works. Several discussions on the same line open together.
In commit views, current-review discussions are mapped to unchanged lines;
comment ranges must remain contiguous and unchanged.
:ReviewThreads opens all discussions, including general comments.

Messages and replies render emoji shortcodes such as :thinking: and :question:
as Unicode emoji, inline and in the discussion window. The bundled gemoji
catalogue needs no network access. Unknown or escaped shortcodes, Markdown code
spans and fenced code blocks stay literal. Draft editors and submission
previews preserve the original text.

In the discussion window, j/k moves through the text, :ReviewJump jumps to the
discussion's file and comment line, and :q closes the window.
:ReviewOpenComment opens the comment or reply under the cursor
in the browser. Discussion headings and file locations open the root comment.
:ReviewJump works from headings, locations, messages and replies.
Enable keymaps.select_comment for a jump shortcut.
The jump focuses the appropriate old/new side, opens folds and centers the
cursor. When needed, it opens the complete MR/PR comparison.

Older comments are mapped to the current review only when their line is
unchanged. If the line was rewritten/deleted, the file is no longer in the
review diff, or its original revision is unavailable, the discussion stays
open with an explanatory message. General comments have no line to jump to.

COMMENT URLS                                            *review-comment-urls*

:ReviewOpenComment opens a comment with vim.ui.open.
In the diff, any line inside its range works. Select a discussion if several
cover the line; its root comment opens. In a discussion window, the comment or
reply under the cursor opens. General, resolved and outdated comments can also
be opened when their URL is available.

GitLab links use the note ID. GitHub and Codeberg use the comment URLs returned
by their APIs. Missing URLs and browser launch errors display a message.
Local drafts have no published URL.
Set keymaps.open_comment to enable a shortcut in both the diff and discussion
windows. It defaults to false; the command is always available.

INLINE DISCUSSIONS                                    *review-inline-comments*

:ReviewToggleComments shows/hides discussion blocks below their
commented lines. Range comments appear below the last line. Authors, messages
and replies are displayed; multiple discussions on one line appear together.
Only discussions mapped to the current diff are shown. General comments and
unavailable lines remain accessible through :ReviewThreads.

Blocks use virtual lines, preserving the diff content and comment positions.
Long lines wrap to the window width. Markdown is shown as text; :ReviewThread
opens the full discussion in a Markdown window. Local drafts retain compact markers.

inline_comments defaults to false. Set it to true to show blocks initially.
The toggle is scoped to the open review and survives navigation and refresh.
Set keymaps.toggle_comments to enable a shortcut; it defaults to false.
Customize ReviewCommentBorder, ReviewCommentAuthor and ReviewCommentBody.

REPLIES                                                      *review-replies*

:ReviewReply opens a Markdown reply editor for the discussion
attached to the cursor line. Any line in a commented range works. When several
discussions cover the line, a selector shows their authors and messages.

Replies are persistent local drafts. :w saves locally; :q! cancels.
:ReviewDrafts edits/deletes replies, and the diff labels them as "local reply".
:ReviewSubmit previews the original comment and reply before publication.
It checks the diff refs and verifies that the original comment still exists.
Failures retain drafts; uncertain outcomes block automatic retries.

GitLab adds a note to the existing MR discussion. GitHub replies to the
top-level PR review comment. Codeberg reply drafts are not supported.
Replies do not approve a review or change discussion resolution.
Set keymaps.reply to enable a shortcut; it defaults to false.

CONFIGURATION                                                  *review-setup*

>lua
    require("review").setup({
      panel_width = 44,
      inline_comments = false,
      keymaps = {}, -- all mappings disabled
      clone_protocol = "ssh",
      repo = nil,
      cache_dir = vim.fn.stdpath("cache") .. "/review",
      state_dir = vim.fn.stdpath("state") .. "/review",
    })
<

Optional mappings: add this table to the setup call above. Every value is a
user choice; remove entries or set them to false to leave the keys available.
The README includes the same example.

>lua
    keymaps = {
      -- Panel and diff, normal mode.
      next_commit = "]c", prev_commit = "[c",
      next_file = "]f", prev_file = "[f",
      next_hunk = "]h", prev_hunk = "[h",
      complete = "<leader>ra", drafts = "<leader>rd",
      threads = "<leader>rT", submit = "<leader>rs",
      refresh = "<leader>rr", info = "<leader>ri", help = "<leader>r?",
      toggle_comments = "<leader>rt", toggle_viewed = "<leader>rv",
      files_picker = "<leader>rF",
      close = "q",
      -- Diff only; comment also works in visual mode.
      comment = "<leader>rc", reply = "<leader>rR", thread = "<leader>rl",
      open_comment = "<leader>ro", -- also in discussion windows
      -- Panel only.
      search_files = "<leader>rf",
      panel_open = "<CR>", panel_left = "h", panel_right = "l",
      panel_toggle = "za", panel_expand = "zo", panel_collapse = "zc",
      panel_collapse_all = "zM", panel_expand_all = "zR",
      filter_exit = "<Esc>", -- filter input, normal/insert mode
      -- Review document/comment windows.
      close_document = "q", select_comment = "<CR>",
      save_draft = "<C-s>", -- comment editor, normal/insert mode
      -- Extra pipeline picker shortcuts, insert/normal mode.
      pipeline_open = "<C-o>", pipeline_back = "<C-b>",
    }
<

An existing matching repository is used without switching branches.
Otherwise the plugin fetches a bare repository into cache_dir.
Local drafts are stored in state_dir/drafts/.

FILE FILTER                                                   *review-filter*

The field sits below the review title, statuses and viewed progress, just above
the commit/file tree. While scrolling, it follows that position and stays at the
top once the review information scrolls out of view. It filters the current
commit or complete comparison using case-insensitive literal path fragments.
Whitespace separates terms; every term must match the old or new file path.
Example: transformation/ sql. Parent folders, Git statuses and viewed markers
remain visible. Empty results leave the current diff open.

The query survives commit navigation and refreshes. Next/previous file commands
skip hidden files. Active filtering has separate folds; :ReviewFilesClear
restores the previous unfiltered tree. Selecting a hidden file through a
discussion jump or :ReviewFilesPicker clears the query to reveal that file.
The sidebar filter needs no picker dependency.
Customize ReviewFilterBorder and ReviewFilterPrompt.

==============================================================================
COMMENT POSITIONS                                            *review-comments*

Commit-view comments are mapped to the current MR/PR diff, not posted as standalone
commit comments. A line rewritten by a later commit must be selected again in
the complete MR/PR view (:ReviewComplete). Ranges must cover one contiguous
side of the diff.
Providers require the selected lines to be inside their diff context.

GitHub uses line/side and start_line/start_side for ranges. Removed lines
belong to LEFT; added/current lines belong to RIGHT.
GitHub's REST API does not expose a discussion's resolved state. Outdated
comments are labeled. PRs with more than 3000 changed files are rejected
because the files API cannot return a complete list. Commit lists above 250
entries use the paginated comparison API with a matching PR commit count.

Codeberg uses old_position/new_position for the first selected line and
extra_lines_count for a range. Each local draft creates one COMMENT review.
Codeberg can include existing pending browser comments when creating a review;
the plugin checks for a pending review before sending each draft. If one exists,
local drafts remain saved until the browser review is finished or discarded.
Review comments appear individually with resolved/stale indicators when exposed.
Comments whose commit cannot be matched to the current diff remain readable in
:ReviewThreads without an inline marker.

GitLab's discussion card can show up to 16 diff lines ending at the comment's
last line. The range shown below the excerpt is the actual commented range.
The discussion API does not expose a context-size option.

If a publish request's outcome is unknown, automatic retry is blocked. Check
the provider and use :ReviewDrafts to explicitly allow retry or delete the draft.
